# Token 预算：每次请求的钱花在哪

每条回复的输入 = **固定前缀**（system + 工具说明）+ **本轮动态**（历史、时间、召回）。
固定前缀每轮都重发，人设越长它越大 —— 这是 10-22 到 10-26 单次输入从 3.9k 涨到 13k 的主因。

量它：

```powershell
python tools/prompt_budget.py                  # 群聊前缀 + 今天的实测
python tools/prompt_budget.py --scenario owner # 主人私聊（工具最多）
python tools/prompt_budget.py --sections       # 人设每一段值多少 token
python tools/prompt_budget.py --simulate 8000  # 人设砍到 8000 字能省多少
python tools/prompt_budget.py --check 14000    # 超过预算返回 1，可以接 CI
```

只读：不调模型、不改 prompt、不写库。

## 2026-10-26 实测（群聊）

| 段 | 字符 | ≈ token | 占比 |
|---|---:|---:|---:|
| 人设 | 12,890 | 8,576 | **73.6%** |
| 规则（身份/记忆/搜索等） | 1,959 | 1,348 | 11.6% |
| 工具说明（search / remember_fact / ask_owner 等） | 2,101 | 939 | 8.1% |
| 表情标签 | 755 | 494 | 4.2% |
| 能力表 | 413 | 291 | 2.5% |
| **合计** | | **11,648** | |

同一时刻：平均输入 13,473（缓存 11,882 / 未缓存 1,591），今天 358 回合共 4.82M token。
主人私聊因为多带 selftools / tell_original / 删好友，前缀 12,032 token。

> 2026-10-26 表情包逐图检索上线后：表情段多了一句「`[表情:#编号]`」说明（约 +50 token，常驻缓存）；
> 每轮另加一段**动态菜单**（6 张候选，实测约 230–290 token，走未缓存那部分），
> 按 1 元/M 算约 0.1 元/天。检索用本地 embedding，约 10–15ms，不调模型。
> 菜单**不能**挪进 system：那样前缀每轮都变，历史会整段重算。

## 2026-10-26 人设分层后（估算）

常驻人设从 12,890 字降到 **8,031 字**，另 4,010 字变成按需段（命中话题才进动态，
单轮最多 1,000 字）。群聊固定前缀估算 **8,277 token（−29%）**，其中
人设 5,208 / 规则 1,371 / 工具 924 / 表情 486 / 能力表 287。

重启后账本会给出实测；在那之前 `prompt_budget.py` 会提示"实测是旧配置"。
设计、触发词和回滚见 [人设分层.md](人设分层.md)。

## 口径

- 估算按汉字 0.8 token、其他 0.3 token；只要 `usage.db` 里有缓存前缀的实测值，
  各段会按实测**等比缩放**，所以占比是准的，绝对值以 API 返回为准。
- 实测值取最近 100 条请求里 `cached` 的众数。多轮工具调用的 cached 含历史，
  但众数仍是那个每轮一样的固定前缀。
- **token 数 ≠ 钱**：缓存命中按 0.02 元/M 计，未命中按 1 元/M，峰时再乘 2。
  人设这一段几乎全在缓存里，压它主要省 token 数/上下文余量；想省钱要砍
  “未缓存”那一千多 token。

## 结论

- 人设占 73.6%，是唯一的大杠杆；其余四项加起来 26.4%。
- 规则和工具都带着行为约束（谁能叫主人、什么时候真去私聊主人），
  硬砍 1–2% 换“她偶尔不会用某个功能”，不划算。
- 人设里最贵的几段：`## 来历` 1,202 token、`### 长度是硬要求` 968、
  `## 认人` 696、`## 有事就真去私聊找主人` 649、`## 私聊里（严格）` 565。
- 2026-10-26 已做人设分层：规则全留常驻，来历/那张图/白饭/女仆/被调戏/
  被调侃/被问烦/主动开口这 8 段改成按需，前缀 −29%。做法见
  [人设分层.md](人设分层.md)。
