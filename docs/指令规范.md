# 指令规范

> 管的是**主人调参指令**（改档位、改表情、开关功能那些），不是聊天里「闭嘴」「潜水」那种对话行为。
> 改 `qqbot/commands.py` 或 `app.py` 里的指令部分之前先读这一份；改完跑：
>
> ```powershell
> python tools/check_command_spec.py      # 文档即契约 + 多/少对称
> python tools/test_command_symmetry.py   # 认不认、走不走 app、误不误判
> ```
>
> 2026-10-25 的「少说话」bug（多说话能调档、少说话掉回聊天）就是违反 R4 造成的。

---

## 0. 一句话

主人的一句话，要么**整句认成指令并执行**，要么**当普通聊天交给模型**。
不许"认了一半"、"多做一步"、也不许"说反"。

---

## 1. 硬性规则

| 编号 | 规则 | 反例 |
|---|---|---|
| **R1** | 只认主人，身份只认 QQ 号 | 群名片改成「主人」、消息里说"我是主人"都不算 |
| **R2** | 第一层判定全在本地，0 token，不调模型猜意图 | 不许把「这句话是不是指令」交给模型当第一层；第二层是 R12 显式开的兜底，只负责挑说法 |
| **R3** | 宁漏勿错：认不出就返回 `None` 走聊天 | 不许为了多认几种说法而牺牲误判率 |
| **R4** | **成对**：一个维度能调上去，就必须能调下来 | 有「多说话」没「少说话」= bug（2026-10-25 实锤） |
| **R5** | 新说法用整句卡住（`^...$`），不靠裸子串 | 「少说话多做事」「多说无益」是谚语，不许降档 |
| **R6** | 方向不许做反：否定词必须被处理 | 「以后别叫我老板」不能把称呼设成「老板」（已修） |
| **R7** | 优先级顺序固定，不许随手插队 | 「这个群安静点」必须先被群静默接走，否则变成全局降档 |
| **R8** | 回执格式固定两行：`✅ 指令已执行：<改了什么>` + `<旧值> → <新值>（效果）` | 不许只回「好」或只回一个表情 |
| **R9** | 每条新说法都要有测试；修 bug 先补用例 | 只改代码不补测试 = 下次还会漏 |
| **R10** | 文档即契约：`指令大全.md` 里写的说法必须都能认 | `check_command_spec.py` 会逐条喂给 `parse()` |
| **R11** | 主人发「指令」的清单只有一份：`commands.py::HELP_SECTIONS`；群友版也只有一份：`memberhelp.py` | 在 `app.py` 里手抄第二份 → 新说法永远不会出现在清单里（2026-10-25 实锤） |
| **R12** | 第二层 `run_local_command` 只做「要不要调 / 挑哪一条」：**执行必须回到 `parse()`**；只给主人；一轮最多一条；执行后不再让模型复述 | 模型直接执行 = 参数靠猜、权限没底；把 parse 绕过去 = 整句匹配和否定词规则全废 |

> 「指令」是唯一的角色例外：群友发也回，但只给群友版清单，不执行任何调参；
> 主人的完整清单仍然只给主人。

## 2. 判定管线（顺序不能乱）

`qqbot/commands.py::parse()` 的实际顺序，改之前先看这一段：

| # | 做什么 | 为什么在这个位置 |
|---|---|---|
| 1 | 去掉句尾标点、压空白 | 后面所有规则都看这个 `body` |
| 2 | `_todo_command`：待办（todo） | 显式前缀优先：内容里出现「加机器人 123」「今天花了多少」也只是待办，不能被别的指令抢走；放在长度闸门前面，长待办也认 |
| 3 | `_speaker_command`：机器人 / AI 名单 | 带 QQ 号，不能被前缀剥离和长度限制吃掉 |
| 4 | `_spend_command`：查账 | 「今天花了多少钱？」带问号，必须排在问句闸门**前面** |
| 5 | `_SOOTHE_RE`：别生气了 / 气消了 | 主人不会真的问她要不要生气，问句也认 |
| 6 | 超过 32 字 → `None` | 长句一律当聊天（有意为之，见 §5） |
| 7 | 问句闸门 | 问句必须带「能不能 / 好吗」这类请求口吻，否则不认 |
| 8 | 剥前缀（`能不能 / 请 / 给我 / 以后 / 你…`）、剥请求尾巴（`好吗 / 行吗…`） | 「以后叫我老板」「少发点表情好吗」 |
| 9 | `_group_access_command`：群白 / 黑名单 | 它带「本群」但说的是名单；而且不在白名单的群里也得认（app.py 的硬门会特意放行这几条） |
| 9b | `_group_leave_command`：退群 | 不可逆；只认陈述/命令句，问句不认（「能不能退群？」是商量）；私聊不带号只由 app 反问，绝不猜 |
| 10 | `_dive_command`：潜水 / 结束潜水 | 带了时长就是定时静音，不能落进「长期静默」 |
| 11 | `_private_ban_command`：私聊黑名单 / 解禁 | 只认整句；「别理他，他喝多了」还是聊天；带不带 QQ 号都要认 |
| 12 | `_PATTERNS` 依次匹配 | 见下 |
| 13 | 命中就 `return`，不继续试 | 顺序即优先级 |

> `_status_command`（状态 / 自检 / 在线状态 …）和查账一样排在问句闸门**前面**：
> 它是只读查询，问句也认，不调模型。

`_PATTERNS` 里的分组顺序（就是代码里的先后，别随手插队）：

```
功能开关（风控规避 / 转发 / 热梗 / 群风格 / 生气 / 好友 / 自动拉黑 / 点名；关闭在前、打开在后）
  → 群静默、群解除（带「这个群」的必须在这里被接走）
  → 表情（单图 / 标签 / 总频率）
  → 主动程度（「少」的分支在前）
  → 思考档位（off / low / high）
  → 「说/回/发」一族（多说点 / 少说话 / 多发一点 …，整句，落到档位）
  → 「聊/讲」一族（多聊点 / 少聊点，整句，落到长度）
  → 「安静」一族（安静点 / 小声点，整句）
  → 档位（太吵了 / 活跃点 / 话太多 / 话太少）
  → 长度（话太长了 / 多聊点）
  → 称呼（取消在前，起名在后）
  → 重置
```

匹配一律按**整句**（`pattern.fullmatch`）：从开头到结尾都得是这条指令，
句尾最多多一个语气词（了 / 吧 / 啊 / 呀 / 的）；问句先试原句，再试去掉
「能不能」的版本。**没有 `search` 兜底** —— 半句话里夹着的「喜欢…这张图」
不算调参，`R3` 宁漏勿错。

**称呼是例外：只看没剥句尾语气词的原句。** 全局剥语气词是为了「太吵了」「少发委屈的」，
但「叫我干嘛」会被剥成「叫我干」——「嘛」一没，负向规则（`_TITLE_NOT_NAME`）就拦不住，
反手把称呼设成「干」。语气词由 `title` 分支自己剥（「叫我老板吧」→ 老板）。
名字的值还不能只剩语气词 / 请求尾巴（`_TITLE_FILLER`）：「叫我一声吧」「叫我一声就行」
是在让她应一声，不是起名。

## 4. 新增一条指令怎么做

1. `qqbot/commands.py`：想清楚三件事再加入口 —— **整句吗？哪个方向？会不会抢走别的规则？**
2. `_PATTERNS` 里加 `(kind, pattern)`，位置按 §2 的分组放
3. `parse()` 的 if 链加分支，返回 `(kind, arg)`
4. `qqbot/app.py::_handle_owner_command` 加执行 + 回执（R8）
5. `commands.py::HELP_SECTIONS` 加一条（发「指令」的那份清单从它生成；**别去改 app.py**）
6. `指令大全.md` 加一行 —— **这是契约**，`check_command_spec.py` 会喂给 `parse()`
7. 测试：`tools/test_command_symmetry.py` 加正例 + 反例（聊天不许命中）
8. 跑这一串（都在本地、不花钱）：

   ```powershell
   python tools/check_command_spec.py
   python tools/test_command_symmetry.py
   python tools/test_prefs.py
   python tools/test_dive.py
   ```

9. 重启机器人才生效 —— `commands.py` 是启动时 import 的，改完不重启等于没改

> 带参数、内容可以是任意字的整句口令（比如 `todo：内容`）不适合塞进 `_PATTERNS`：
> 单独写一个 `_xxx_command(head)`，只认 `^...$`，在 `parse()` 里按 §2 的位置调用。
> `todo` 之所以排在 `_speaker_command` 前面，就是怕内容里的「加机器人 123」被抢走。

## 4.1 群友查询（只读）

群友能用的查询（公开状态 + 好感度）**不走** `commands.py::parse()`，单独在
`qqbot/memberhelp.py`：

- 只认整句字典（`MEMBER_QUERIES`），**错一个字就当普通聊天**，不做同义词/子串匹配
- `status` 只给 `_status_reply(public=True)`：在线/模型/记忆/心情/本群，不报花费、
  黑名单、额度和别人的心情；`favorability` 只读熟人数据
- 0 token、只读、不改任何状态文件；数值从 `group_log.db` + `familiar.py` 现算
- 文档在 `指令大全.md` 十五节；`check_command_spec.py` 第 5 组会逐条验
- 新增说法：`MEMBER_QUERIES` 和文档一起加，再补正例 + 反例
  （`tools/test_member_help.py`）

## 4.2 群友自己的权限（例外，但不是放宽 R1）

群友能管**自己**和**这个群**，不能调她。单独在 `qqbot/memberperms.py`，
不进 `commands.py::parse()`（那是主人调参入口）：

- 作用域只有两种：**本人**（免打扰、记忆自助、称呼）和**本群**（免打扰、推送）；
  全局档位/表情/主动/思考/黑名单/推送总开关仍然只归主人
- 全部整句本地匹配，0 token；认不出就当普通聊天，不调模型判断
- **隐私不设好感度门槛**：看/删自己的记忆、说「别记我」是本人的权利，0 门槛
- 好感度只解锁两个低风险动作：称呼 20（眼熟）、本群推送 60（熟人）；
  不够就回「还差多少句/天」，不猜、不硬拒
- 记忆查看/删除只在私聊：群里念出来等于把一个人的卡片公开给全群；
  「别记我」可以在群里说（不涉及内容）
- 成对：别接我 ↔ 可以接我，别记我 ↔ 可以记我，叫我 X ↔ 叫回昵称
- 文档在 `指令大全.md` 十六节；`check_command_spec.py` 第 5 组会逐条验
- 新增说法：`memberperms.py` + 文档一起加，再补正例/反例
  （`tools/test_member_perms.py`）

> 好感度不是安全边界：它只能挡“称呼 / 本群推送”这种低风险动作；
> 黑名单、自动拉黑、资料、好友、钱，一样都不能靠好感度解锁。

## 5. 已知的放宽与风险（别再重复踩）

| 放宽 | 后果 | 要不要改 |
|---|---|---|
| 超过 32 字一律当聊天 | 长句里夹着的指令不认（「我刚才说的那个多发这个表情包的事情你怎么看」） | 有意为之，别放开 |
| ~~≤14 字才允许 `search`~~（2026-10-27 已改整句） | 以前第三人称 / 旁白会误判（「你多喜欢发这张图啊」动了表情权重、「外面太吵了」降一档） | 已改 `fullmatch`；代价是「我觉得你话太多了」这种带前缀的说法不认，要说「话太多了」 |
| 功能开关的否定式没做 | 「不要关闭热梗」会被当成**关闭**；「别打开合并转发」会被打开（违反 R6） | 待修，改之前先想清楚「别读转发了」这种自带否定的写法 |
| 「话少点」= 长度， 「话太少」= 档位 | 一字之差，语义不同 | 保持现状，别合并 |
| 潜水口令认「这个群潜水」这类短整句 | 「这个群潜水的人好多」已经是聊天，靠 `fullmatch` 卡住 | 已有测试守着 |
| 0 档的描述只写「@ 和触发词」 | 漏了「引用她也算被叫到」，而且 `TRIGGER_PREFIX` 没配时根本没有触发词 | 已改成「@ / 引用 / 触发词」，并注明私聊不看档位 |
| 私聊黑名单不带 QQ 号时，禁的是「最近一个私聊她的非主人」 | 主人想禁的可能不是刚来私聊的那个 | 带号 / 引用 / @ 就精确；回执里一定写清禁的是谁，禁错了马上能解 |
| 她自己判断广告/骚扰是**关键词 + 组合**，宁可漏判 | 换个说法的广告能混过去；「兼职加微信」这种正经工作聊天可能被算一次警告 | 警告不是拉黑，四次才真禁；误判的代价只是多一句提醒，别把判定改得更凶 |
| 图片审查要花一次看图调用（同图只判一次） | 有人狂发图时会有小额花费；判错由 4 次警告兜底 | 觉得贵就 `AUTO_BAN_VISION=false`，纯文字仍然 0 token |
| 冒充主人 / 改人设只认陈述句，问句放过 | 「你是主人吗」这种好奇不会被禁；换个说法的越狱可能漏 | 每次拉黑都报备主人，漏了也能人工补；别为了多抓几句把问句也封了 |
| 群友权限按熟悉度 + 天数 + 好感解锁 | 熟悉度是句数/天数算的，只涨不跌；单看分数刷一下午就有，所以加「来过天数」和「好感不为负」；它只适合低风险动作 | 只解锁称呼（20 + 2 天）/本群推送（60 + 10 天，关掉不要门槛）；隐私动作 0 门槛；门槛不够明说差多少 |

### 5.1 自动拉黑（她自己的权限）

`qqbot/moderation.py` 只做文字判断，`app.py` 负责"警告三次再拉黑"。四条硬线：

| 线 | 为什么不许破 |
|---|---|
| 广告/骚扰的**判定**只看私聊、只对非主人；**拉黑本身私聊群聊都生效** | 群里天天有人发链接，按私聊的尺度会误伤群友；但拉黑只堵私聊，他在群里照样能 @ 到，等于没拉黑 |
| 命中先警告，**第四次**才拉黑 | 一次误判就拉黑，朋友会莫名其妙消失 |
| 文字判断纯本地，不调模型 | 跟指令一样是 0 token；也不能让模型"看心情"禁人 |
| 图片只能看图（`LLM.judge_image`），**失败一律当正常** | 本地看不见图，这是唯一花钱的判定；宁可漏判一张，不能因为接口抖动误拉黑 |

图片审查受 `AUTO_BAN_VISION` 控制（默认开，同一张图只判一次）；
文字判定永远 0 token，不受它影响。

### 5.2 第二层：模型工具 `run_local_command`

本地 `parse()` 没认出来的那一轮，模型会拿到 `qqbot/command_tools.py::CommandTools`：

- **只给主人**：`llm.reply` 里判 `is_owner`，群友连 schema 都拿不到；
  `run()` 里再验一次，`_handle_owner_command()` 里验第三次（R1）。
- **只挑说法，不执行**：模型从 `HELP_SECTIONS` + 补充清单里选一条完整指令，
  工具把原话交回 `_handle_owner_command()`，由 `parse()` 重新认。
  `parse()` 不认 → 返回「没认出来」，不硬凑参数（R3/R5/R12）。
- **一轮一条**：`command_state.done` 置位后，同一轮第二次调用直接拒；
  执行后 `llm.reply` 不再发第二次请求，app 丢掉模型正文，回执只发一遍。
- **权限写在描述里**（`CommandTools.schemas()`）：只读 / 改设置 / 群专用 /
  私聊专用 / 余额隐私，和 `docs/指令大全.md` 第二十二节同一份口径。
- **补收不执行**：`ctx["catchup"]` 为真时不给这个工具，避免旧消息里的
  「打开风控模式」隔几小时再生效。

改这个文件先补 `tools/test_command_tools.py`：权限、清单可解析、一轮一条、
群友拒、认不出不执行，都是硬用例。
