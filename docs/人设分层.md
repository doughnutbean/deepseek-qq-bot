# 人设分层：常驻规则 + 按需故事

人设原文 12,890 字，原来整份进 system，占每次请求固定前缀的 **74%**。分层后：

| | 字符 | 约 token | 去向 |
|---|---:|---:|---|
| 常驻（core） | 8,031 | 5,208 | system，每轮都发，字节稳定吃缓存 |
| 按需（on_demand） | 4,010 | 2,600 | 命中话题才追加到**动态上下文**，不进 system |
| 只对群聊 / 只对私聊 | 849 / 766 | — | 群聊不带「私聊里」，私聊不带「群聊里」「群里的说法」 |

群聊固定前缀估算从 **11,648 → 8,277 token（−29%）**。按需段平均只在少数回合出现，
单轮最多 1,000 字，同一段 15 分钟内不重复注入。

## 文件

- `persona.md` —— **一个字没改**，仍然是人设唯一原文。
- `persona.layers.json` —— 只写分类和触发词，不写人设正文：
  - `core`：常驻段（标题必须和 `persona.md` 的 `##` 标题一致）；
  - `context_only`：`{"段落": "group"}` 或 `"private"`，只对一种会话生效；
  - `on_demand`：`{"段落": ["触发词", ...]}`，命中才注入；
  - `max_chars`：单轮按需注入的上限（默认 1000）。
- **没写进表的段一律当 core**（安全侧）：宁可多花钱，也不能把人设弄丢。

## 回滚（出问题时按这个顺序）

1. **立刻回滚，不用重启**（下一轮请求生效）：
   ```powershell
   python tools/persona_layers.py --off
   ```
   它只是建一个 `data/persona_layers.off`；每轮请求都会看这个文件。
   恢复分层：`python tools/persona_layers.py --on`。
2. **重启级回滚**：`.env` 里写 `PERSONA_LAYERS=full`，重启。
3. **自动兜底**：分层表缺失、JSON 写坏、组装抛异常，都会自动退回整份人设，
   只在日志里留 warning，不会耽误说话。
4. **代码级回滚**：整个功能就是 `qqbot/persona_layers.py` + `persona.layers.json`，
   删掉这两个文件就回到「整份人设进 system」的老行为（`app.py` 里只剩一行
   `plan = getattr(self, "persona_plan", None)` 的兜底）。

回滚是逐字节回到整份人设：`plan.core()` 在 full 模式下直接返回 `persona.md` 原文。

## 改分层表

- 把某段从 `core` 挪到 `on_demand`：在 JSON 里移动 key，并给它写触发词；
  改完跑
  ```powershell
  python tools/persona_layers.py --check
  ```
  检查会盯着：有没有漏分类/多写的段、触发词空、`context_only` 值不合法、
  按需和上下文段撞车。
- 改完要**重启**才换 system（常驻段变了）；`--off/--on` 是例外，下一轮就生效。
- 想调单轮注入上限：改 `max_chars`（200–4000）。太小会讲不清来历，太大就白分层了。

## 注意

- **token 数降了，钱不一定同比例降**：常驻段在缓存里按 1/50 价计费，按需段
  是未缓存的全价。触发得越频繁，省的钱越少。这里的目标是降 token 数/上下文余量，
  省钱要另算（见 [Token预算.md](Token预算.md)）。
- **触发词可能漏**：她突然不讲来历了，先看 `--check` 有没有这个段，再往它的
  触发词里加词。宁可少触发，也不要把整段常驻加回来。
- **冷却 15 分钟**：同一会话同一段不重复注入，防止一句一个「饭」把动态上下文撑爆。
- **分层表按标题匹配**：改 `persona.md` 的 `##` 标题会让对应段变成未分类 → 按 core
  处理（安全），但 `--check` 会红，提醒你同步。
